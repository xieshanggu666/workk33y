# 末日地堡生存

一款基于 **FastAPI + SQLite** 后端与 **Vue 3（本地运行时，离线可用）** 前端的末日地堡模拟经营游戏。

## 游戏说明

地表已覆灭，你带领一批幸存者藏身地堡。你需要管理**有限的食物、水源、电力、氧气**，安置与分配**居民岗位**，扩建**基础设施**，并在每天的**危机轮盘**中做出抉择，坚持到第 120 天迎来曙光。

## 核心机制

- **资源守恒循环**：每日净变化 = 设施产出 − 人口消耗。产出受设施等级、相关岗位（农民/工程师）与平均士气加成影响。
- **四类资源**：食物 / 水源 / 电力 / 氧气，任一枯竭都会引发减员。
- **居民管理**：每位幸存者有健康与士气，健康低于阈值士气下滑；士气影响整体产出效率。可为居民指派岗位（工程师 / 农民 / 杂工）。
- **设施扩建**：穹顶菜园（产食物）、净水器（产水）、发电机（产电）、水培制氧（产氧）、医疗舱（回血）、仓储区。可建造与升级（等级加成 x1.6）。
- **危机轮盘**：每天约 45% 概率触发危机事件，均可多选决策（辐射风暴、内讧、氧气泄漏、疫病、盗匪、物资舱、暴雪、商路盗匪），不同选择带来不同的资源 / 健康 / 士气后果。
- **探索队派遣**：选派在堡居民携带物资外出，途中触发独立的探索遭遇（废弃补给、异兽、天气、偶遇幸存者等），返程统一结算战利品、余粮与伤亡。
- **贸易救援**：地堡与外部聚落围绕订单、物资和信誉协商。外部队伍会主动发来贸易/救援申请（限时审核），管理者也可主动申请商路订单；订单沿 **申请 → 审核 → 运输 → 交付 / 失败回退** 的状态链推进，结果回写资源、居民（获救者加入 / 押运伤亡）、士气与信誉；商队遇袭会回写为地堡危机。信誉越高外部越容易接单、商路风险越低。
- **结局结算**：存活至第 120 天**胜利**；人口归零或四资源全线枯竭则**失败**。胜局 / 败局均按幸存者 × 天数 × 士气系数结算评分。

## 快速开始

环境要求：**Node.js**（任意近年版本，仅用于命令调度，前端无需构建）与 **Python 3.10+**。
前端静态资源由 FastAPI 后端同端口托管，因此一条命令即可启动前后端：

```bash
npm run setup   # 安装 Python 依赖并初始化数据库（仅需一次）
npm start       # 一键启动前后端
```

访问 http://127.0.0.1:8000 ，在档案大厅新建或继续一局游戏。

| 命令 | 作用 |
|---|---|
| `npm run setup` | 安装 Python 依赖 + 初始化数据库（幂等，含演示档案） |
| `npm start` | 生产模式启动（`PORT=8080 npm start` 可换端口，`HOST`/`PYTHON` 同理） |
| `npm run dev` | 开发模式启动（代码变更自动重载） |
| `npm run init-db` | 仅初始化/补齐数据库 |
| `npm test` | 运行 pytest 测试套件（`npm test -- -k xxx` 可透传参数） |

## 状态流转与一致性约定

档案状态机只有四个阶段，所有后端守卫以前端禁用为辅助、以后端校验为准：

| 阶段 | 含义 | 允许的动作 |
|---|---|---|
| `daily` | 每日阶段 | 建造/升级/调岗/派遣探索队/申请·审核贸易订单/推进一天 |
| `crisis` | 地堡危机待处理 | 仅结算当前危机 |
| `expedition` | 探索遭遇待处理 | 仅结算当前遭遇 |
| `ended` | 胜利/失败终局 | 只读，拒绝一切变更 |

- **每日推进**：`daily → 产出消耗/健康士气 → (行军+遭遇? | 贸易订单推进 | 危机? | 终局)`。抉择不可被“再点一天”跳过。
- **探索队**：离堡人员暂停地堡生产、不消耗地堡口粮、不参与地堡危机效果；行军消耗自带口粮，遭遇替代当日地堡危机，返程统一结算战利品/余粮/伤亡。终局日队伍仍在外时先安全返程再收敛到 `ended`，不留“僵尸队伍”。
- **贸易救援订单**：`applied(申请/审核) → transporting(运输) → delivered(交付) | failed(失败回退) | rejected(拒绝)`。外部聚落的 inbound 申请 3 天内不审核自动判拒绝；地堡 outbound 申请在次日推进时由外部按信誉概率审核，通过才托管押金、商队启程。在途商队每日随推进抽风险：送达回写资源/获救居民/士气/信誉，盗匪截击半额退款、押运员受伤并把 `trade_raid` 危机挂入地堡危机流程，风暴全额退款不挂危机；终局时未结束订单统一 `aborted` 且押金全额退回。押运员与探索队共用“离堡人员”口径（暂停生产/口粮、不吃地堡危机），两类任务可同时进行但同一居民不能重复外出。
- **并发**：`row_version` 乐观锁保证每日推进/危机/遭遇/返程/贸易审核只落一次；落败方凭一次性 `token` 与档案级幂等凭据（`last_resolution` / `last_expedition` / `last_trade`）安全回放，过期或串档请求返回 409。
- **旧存档**：启动时自动补列（`pending_crisis` / `last_resolution` / `expedition` / `last_expedition` / `reputation` / `trade_orders` / `last_trade` / `row_version`），并归一化损坏/悬空快照（已结束档案清除悬而未决状态、失踪成员/目标/押运员剔除、悬空订单按状态清理、`survivors` 与居民表对齐），归一化本身幂等。
